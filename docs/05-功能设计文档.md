## 1. 概述

### 1.1 背景与目标

用户希望记录"某个重要日子"并随时看到它"已经过去多少天 / 还有多少天"。「终末时记」以**彩色卡片**的形式管理这些里程碑，强调低负担记录与一目了然的天数反馈。

### 1.2 范围

**包含（v1.1）**：新增/编辑里程碑（内容/分类/日期/颜色/内容详情）、卡片列表展示天数、卡片详情页、内容详情页、分类下拉选择（模糊搜索）、顶部分类过滤、长按删除、本地持久化、数据导出/导入（换机迁移）。

**不包含**：登录/账号、云同步、桌面小组件、提醒通知（列入 §10 扩展规划）。

### 1.3 名词定义

| 名词 | 定义 |
| --- | --- |
| 里程碑（Milestone） | 一条记录：分类 + 内容 + 目标日期 + 卡片颜色 + 可选内容详情 |
| 目标日期 | 用户选择的日期，可为过去（纪念日型）或未来（倒计时型） |
| 天数差 | 目标日期与"今天"之间相差的自然日数 |
| 分类（Category） | 字符串标签，含默认分类与用户自定义分类 |
| 内容详情（Detail） | 可选长文本（≤ 1000 字），仅详情页内查看，不在卡片上展示 |

## 3. 数据模型设计

### 3.1 实体：MilestoneEntity（Room 表）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | Long | 主键，自增 | 记录唯一标识 |
| content | String | 非空，≤ 50 字 | 里程碑内容，如"坚持早起" |
| category | String | 非空，≤ 10 字 | 分类名，如"生活"；自定义分类同表存储 |
| targetDate | Long | 非空 | 目标日期，存 epochDay（LocalDate.toEpochDay） |
| colorHex | String | 非空，形如 `#66CCFF` | 卡片颜色，取自预设色板 |
| detail | String | 非空默认 `''`，≤ 1000 字 | 内容详情，选填；空串表示未填写 |
| createdAt | Long | 非空 | 创建时间戳（毫秒），用于排序 |
| sortOrder | Int | 默认 0 | 预留：手动排序 |

建表 SQL：

```sql
CREATE TABLE milestone (
    id         INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL,
    content    TEXT    NOT NULL,
    category   TEXT    NOT NULL,
    targetDate INTEGER NOT NULL,   -- LocalDate.epochDay
    colorHex   TEXT    NOT NULL,
    detail     TEXT    NOT NULL DEFAULT '',  -- 内容详情(≤1000字)
    createdAt  INTEGER NOT NULL,
    sortOrder  INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_milestone_category ON milestone(category);
```

### 3.2 DAO 接口

```kotlin
@Dao
interface MilestoneDao {
    @Query("SELECT * FROM milestone ORDER BY createdAt DESC")
    fun observeAll(): Flow<List<MilestoneEntity>>

    @Query("SELECT * FROM milestone WHERE category = :category ORDER BY createdAt DESC")
    fun observeByCategory(category: String): Flow<List<MilestoneEntity>>

    @Query("SELECT * FROM milestone WHERE id = :id")
    suspend fun getById(id: Long): MilestoneEntity?

    @Insert
    suspend fun insert(entity: MilestoneEntity): Long

    @Update
    suspend fun update(entity: MilestoneEntity): Int

    @Query("DELETE FROM milestone WHERE id = :id")
    suspend fun deleteById(id: Long): Int
}
```

### 3.3 分类设计

- 分类**不单独建表**：默认分类 `["生活", "工作", "学习", "纪念日"]` 内置；自定义分类随记录写入 `category` 字段；
- 筛选数据源 = `默认分类 ∪ 已使用的自定义分类`（对现有记录 `SELECT DISTINCT category` 求并集），保证用户自建分类（如"健身"）能出现在筛选面板中；
- 新增/编辑页的**分类下拉面板**复用同一分类集合：输入搜索词即时过滤（包含匹配、不区分大小写），命中字符高亮，无匹配时提供"新建分类「搜索词」"入口，避免分类过多时左右滑动寻找。

### 3.4 UI 模型：MilestoneUi

数据库实体不直接上屏，ViewModel 组装为 UI 模型：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | Long | 同实体 |
| content / category / colorHex | String | 同实体 |
| targetDateText | String | 格式化日期 `yyyy-MM-dd` |
| dayType | enum { PASSED, FUTURE, TODAY } | 天数类型 |
| dayCount | Int | 天数（非负） |
| dayLabel | String | "已过" / "还有" / "就是今天" |
| detail | String | 内容详情全文（可能为空串） |
| hasDetail | Boolean | detail 非空：决定详情页【查看内容详情】按钮可用态 |

## 5. 核心业务规则

### 5.1 天数差计算规则

| 条件（delta = targetDate − today，单位天） | dayType | 展示 |
| --- | --- | --- |
| delta < 0 | PASSED | "已过"，数字 = −delta |
| delta = 0 | TODAY | "就是今天"，数字 = 0 |
| delta > 0 | FUTURE | "还有"，数字 = delta |

### 5.2 排序规则

默认按 `createdAt` 倒序（最新创建在前）。`sortOrder` 字段预留手动排序。

### 5.3 跨天刷新策略

1. 应用**冷启动**时按当前日期计算；
2. 应用**回到前台**（ON_RESUME）时重新计算，避免挂后台跨天后天数滞后；
3. （可选 P2）前台驻留期间注册次日 00:00 的一次性定时任务触发重算。

### 5.4 过滤条件记忆

`DataStore` 保存 `selected_category`；启动时读取并作为初始过滤值，**筛选按钮只显示这一个当前生效标签**。若记忆的分类已无任何记录，筛选按钮仍显示该标签（因属于默认分类或历史上存在），列表区显示空状态即可。

### 6.2 天数差计算（纯函数，可单测）

```kotlin
函数 计算天数状态(targetDate: LocalDate, today: LocalDate): (DayType, Int, String):
    delta ← targetDate.toEpochDay() - today.toEpochDay()   // ChronoUnit.DAYS.between
    如果 delta < 0:
        返回 (PASSED, -delta, "已过")
    否则如果 delta == 0:
        返回 (TODAY, 0, "就是今天")
    否则:
        返回 (FUTURE, delta, "还有")

函数 组装UI模型(实体, today):
    (类型, 天数, 标签) ← 计算天数状态(实体.targetDate 转 LocalDate, today)
    返回 MilestoneUi(
        id        = 实体.id,
        content   = 实体.content,
        category  = 实体.category,
        colorHex  = 实体.colorHex,
        targetDateText = 格式化(实体.targetDate, "yyyy-MM-dd"),
        dayType   = 类型,
        dayCount  = 天数,
        dayLabel  = 标签
    )
```

### 6.4 保存里程碑（新增或编辑：校验 + 写库）

```kotlin
// AddEditScreen 点击「保存」(新增时 id=null,编辑时携带记录 id)
函数 点击保存():
    输入 ← 收集表单(id, 内容, 分类, 目标日期, 颜色, 内容详情)
    ViewModel.保存(输入)

// MilestoneViewModel
函数 保存(输入):
    结果 ← 校验(输入)
    如果 结果.失败:
        发送一次性事件 Toast(结果.错误原因)              // 如"内容不能为空"
        返回
    启动协程(IO):
        实体 ← MilestoneEntity(
            id         = 输入.id ?? 0,                   // Room 自增
            content    = 输入.内容.去空白(),
            category   = 输入.最终分类.去空白(),
            targetDate = 输入.目标日期.toEpochDay(),
            colorHex   = 输入.颜色,
            detail     = 输入.内容详情.去首尾空白(),      // 可为空串
            createdAt  = 输入.id ? 原记录.createdAt : 当前时间戳()
        )
        尝试:
            如果 输入.id 为空:
                Repository.插入(实体)                    // INSERT
                发送一次性事件 (关闭新增页 + Toast("保存成功"))
            否则:
                影响行数 ← Repository.更新(实体)         // UPDATE
                如果 影响行数 == 0:
                    发送一次性事件 (Toast("记录已不存在") + 返回列表)
                否则:
                    发送一次性事件 (关闭编辑页 + Toast("已保存"))
            // 列表与详情页由 Flow 自动刷新，无需手动刷新
        捕获 异常 e:
            发送一次性事件 Toast("保存失败，请重试")

函数 校验(输入) -> 校验结果:
    如果 输入.内容.去空白().长度 不在 1..50:    返回 失败("内容不能为空且不超过 50 字")
    如果 输入.最终分类.去空白().长度 不在 1..10: 返回 失败("分类不能为空且不超过 10 字")
    如果 输入.目标日期 为空:                     返回 失败("请选择目标日期")
    如果 输入.颜色 不在 预设色板:                 返回 失败("颜色非法")
    如果 输入.内容详情.长度 > 1000:               返回 失败("内容详情不能超过 1000 字")
    返回 成功
```

```kotlin
        影响行数 ← Repository.按id删除(卡片id)
        如果 影响行数 > 0:
            // Flow 自动发射新列表 → UI 刷新
            发送一次性事件 Toast("已删除")
        否则:
            发送一次性事件 Toast("删除失败，记录可能已不存在")
```

```kotlin

// 面板搜索框输入(FR-014,输入即过滤,无需点搜索按钮)
函数 搜索词变更(搜索词):

    如果 搜索词.去空白() 为空:

    否则:
        面板状态.结果 ← 全部分类.过滤 { 它.包含(搜索词, 忽略大小写) }
    // 结果行渲染时,命中字符区间用主色高亮

// 点击某个已有分类
函数 选中分类(名称):
    表单.分类 ← 名称
    面板状态.关闭()

// 无满意结果时,点击「＋ 新建分类『搜索词』」(FR-007)
函数 新建分类():
    名称 ← 面板状态.搜索词.去空白()
    如果 名称.长度 不在 1..10: Toast("分类名需为 1~10 字"); 返回
    如果 名称 已存在于全部分类: 表单.分类 ← 名称        // 重名直接选中
```

## 7. 异常与边界处理

| 场景 | 处理 |
| --- | --- |
| 列表为空 | 展示空状态引导文案（不展示其他报错） |
| 内容超长/为空 | 保存时拦截并 Toast 具体原因；输入框实时限制 50 字 |
| 自定义分类重名 | 直接选中已有同名分类，不重复追加 |
| 目标日期为未来远期（如 50 年后） | 允许，天数正常显示"还有 N 天" |
| 目标日期 = 今天 | 显示"就是今天" |
| 数据库写入/删除失败 | try-catch 捕获，Toast 提示，UI 不崩溃、状态回滚 |
| 删除时记录已不存在 | 影响行数 = 0，Toast 提示并刷新 |
| 系统日期被用户改小/改大 | 每次回前台以系统当前日期重算，天然容错 |
| 分类只剩一条记录被删除 | 筛选数据由 `默认 ∪ DISTINCT(category)` 计算，自定义分类自动消失，选中项回退「全部」 |
| 内容详情超过 1000 字 | 输入框实时限制 1000 字（超出不可再输入）；保存校验兜底拦截 |
| 内容详情为空 | 详情页【查看内容详情】置灰禁用；信息面板显示"未填写" |
| 分类搜索无匹配结果（表单面板） | 仅显示「＋ 新建分类『搜索词』」入口，不报错 |
| 分类搜索无匹配结果（首页筛选面板） | 显示"无匹配分类"提示，不提供新建入口（新建分类仅在表单侧） |
| 分类搜索词与已有分类重名 | 点击新建时直接选中已有同名分类，不产生重复分类 |
| 编辑途中记录被他处删除 | UPDATE 影响行数 = 0，Toast「记录已不存在」并返回列表刷新 |
| 内容详情含换行 / emoji | 原样存储与展示，弹层内滚动阅读 |
| 详情页打开时记录已被删除 | getById 返回 null，Toast 提示并返回列表 |

## 8. 状态与事件管理

- **状态（State）**：`HomeUiState` / `AddUiState` 用 `StateFlow` 持有，UI 通过 `collectAsStateWithLifecycle()` 订阅；
- **一次性事件（Event）**：Toast、页面关闭等用 `Channel`/`SharedFlow(replay=0)` 发送，避免重组后重复消费；
- **配置变更**：ViewModel 天然存活于旋转屏幕，订阅不丢；DataStore 保证过滤分类持久。
