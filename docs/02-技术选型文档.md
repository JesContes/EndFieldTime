## 1. 项目概述

「终末时记」是一款本地单机 Android 应用，用于记录里程碑事件（分类、内容、目标日期、卡片颜色），并实时展示该日期距今天的天数（已过 N 天 / 还有 N 天）。技术选型的核心约束：

- **纯本地**：数据不出设备，无需账号体系与网络权限；
- **轻量**：功能聚焦，单一 module 即可，避免过度设计；
- **半平面风 UI**：主色 `#66CCFF`，圆角卡片 + 轻投影，要求 UI 框架对自定义样式友好；
- **可演进**：后续可能扩展编辑、桌面小组件、云同步，架构需预留扩展点。

## 3. 详细选型与理由

### 3.1 开发语言：Kotlin

| 对比项 | Kotlin | Java |
| --- | --- | --- |
| 空安全 | 编译期空检查 | 运行期 NPE 风险 |
| 协程/Flow | 原生支持 | 需 RxJava 等第三方库 |
| 与 Compose 配合 | 唯一官方支持语言 | 不支持 |
| 代码量 | 简洁（data class 等） | 冗长 |

**结论：Kotlin**。Compose 只支持 Kotlin，且协程/Flow 是本项目"数据变更自动刷新列表"的关键基础。

### 3.2 UI 框架：Jetpack Compose + Material 3

| 对比项 | Compose + M3 | 传统 View/XML |
| --- | --- | --- |
| 声明式 UI | ✅ 状态驱动自动重组 | 手动 findViewById + notifyDataSetChanged |
| 自定义卡片/颜色 | `Modifier.background(color, shape)` 一行搞定 | 需自定义 Drawable/Shape XML |
| 半平面风（圆角+轻阴影） | `shadow()` + `RoundedCornerShape` | CardView 嵌套，层级深 |
| 长按手势 | `combinedClickable(onLongClick=...)` | OnLongClickListener 样板代码多 |
| 主题色统一 | `ColorScheme` 集中配置 | 分散在 themes.xml |

**结论：Compose + Material 3**。卡片自定义颜色、长按删除、过滤 Chip 等需求在 Compose 下实现成本最低，主题色 `#66CCFF` 可集中到 `ColorScheme` 管理。

关键 M3 组件映射：自定义筛选按钮（漏斗 + 当前生效标签 + ✕ 重置）+ `ExposedDropdownMenuBox`（**首页筛选与表单分类共用**的下拉搜索面板）、`ModalBottomSheet`（内容详情弹层）、`DatePickerDialog`（目标日期）、`FloatingActionButton`（右下角 ＋）、`combinedClickable`（单击进详情 / 长按删除）。

### 3.3 架构：MVVM + 单向数据流（UDF）

```
UI 层      HomeScreen / DetailScreen / AddEditScreen (Compose)
            │ 事件(onSave/onUpdate/onDelete/onFilter/onOpenDetail)   ▲ StateFlow<UiState>
            ▼                                                        │
ViewModel  MilestoneViewModel —— 天数差计算、校验、状态组装
            │ insert / update / delete / query  ▲ Flow<List<Milestone>>
            ▼                                   │
数据层     MilestoneRepository（唯一数据源抽象，便于将来扩展云同步）
            ▼
本地存储   MilestoneDao(Room) ── SQLite      DataStore(过滤偏好)
```

- **单一数据源**：Room 是唯一事实来源；UI 不直接改列表，增删改都落库，由 Room 返回的 `Flow` 自动驱动刷新（与流程图、时序图一致）；
- **ViewModel 承担逻辑**：天数差计算、输入校验、过滤条件管理，均可脱离 UI 单测。

### 3.4 主存储：Room

| 对比项 | Room | SQLiteOpenHelper | DataStore | Realm |
| --- | --- | --- | --- | --- |
| 结构化查询（按分类过滤） | ✅ SQL 注解 | 手写 SQL，易错 | ❌ 仅 KV | ✅ |
| 编译期 SQL 校验 | ✅ | ❌ | — | ❌ |
| Flow 响应式查询 | ✅ 原生返回 Flow | ❌ 需自行封装 | ✅ | ✅ |
| 实体映射样板代码 | 极少（注解） | 大量 Cursor 代码 | — | 少 |
| 维护方 | Google Jetpack | Android 框架 | Google Jetpack | MongoDB（第三方） |

**结论：Room**。里程碑是结构化数据且需要"按分类过滤"SQL 查询，`@Query` 返回 `Flow<List<Milestone>>` 正好满足"增删后列表自动刷新"。

### 3.5 偏好存储：DataStore Preferences

仅保存轻量偏好（如"上次选中的过滤分类"），替代 SharedPreferences：支持 Flow 读取、协程安全、无阻塞主线程风险。

### 3.6 异步与响应式：Coroutines + Flow

- `Flow` + `stateIn` 将数据库流转换为 `StateFlow<UiState>`，UI 用 `collectAsStateWithLifecycle()` 订阅；
- 增删改用 `viewModelScope.launch { ... }` 一行切换到 IO 线程（Room 挂起函数）；
- 相比 RxJava：无额外依赖、与 Compose/ViewModel 生命周期深度集成。

### 3.7 依赖注入：Hilt

项目仅 Repository / Dao / Database 三个依赖，Hilt 提供标准化注入与 ViewModel 集成（`@HiltViewModel`）。若追求极简，也可用手动 DI（`AppContainer`），见 §7 风险说明。

### 3.8 日期时间：java.time

天数差用 `ChronoUnit.DAYS.between(LocalDate, LocalDate)` 计算，语义清晰、线程安全。`java.time` 在 API 26+ 原生可用，因此 **minSdk 定为 26**，无需 core library desugaring，可减少包体积与方法数。API 26+ 设备覆盖率已超过 95%，可接受。

### 3.9 SDK 与构建

| 配置 | 取值 | 理由 |
| --- | --- | --- |
| compileSdk / targetSdk | 35 | 跟进最新平台行为与合规要求 |
| minSdk | 26 | java.time 原生可用，覆盖 95%+ 设备 |
| AGP | 8.7.x | 稳定版，配合 Kotlin 2.0 Compose 编译器插件 |
| 依赖管理 | Version Catalog（`libs.versions.toml`） | 版本集中、可维护 |

## 7. 风险与备选方案

| 风险 | 影响 | 备选/缓解 |
| --- | --- | --- |
| 团队对 Compose 不熟 | 上手成本 | 备选 View/XML + RecyclerView + CardView；但长按、动态卡片实现成本上升 |
| minSdk 26 放弃 26 以下设备 | 约 <5% 老设备不可用 | 开启 coreLibraryDesugaring 即可降到 21 |
| Hilt 引入复杂度 | 小项目偏重 | 降级为手动 DI（AppContainer + ViewModelFactory） |
| 纯本地方案日后要云同步 | 数据迁移 | Repository 抽象层已隔离数据源，新增 RemoteDataSource 即可 |
| 跨天未刷新 | 天数显示滞后一天 | 见《功能设计文档》§5.3：回前台重算 + 可选午夜定时器 |

## 8. 结论

最终选型：**Kotlin 2.0 + Jetpack Compose(Material 3) + MVVM/UDF + Room + DataStore + Coroutines/Flow + Hilt，minSdk 26 / targetSdk 35**。该组合以最小成本覆盖"分类过滤、彩色卡片、长按删除、天数自动刷新、纯本地存储"全部需求，并为后续编辑、小组件、云同步预留了清晰的扩展点。
